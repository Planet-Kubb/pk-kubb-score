# Agent guide: pk-kubb-score

The Planet Kubb Notation: 150 archived games, a formal grammar, and a static website (docs,
scoresheet, stats). `README.md` covers the layout, the file format and how to rebuild things.
This file holds what the README doesn't: where everything came from, the decisions already
made, and what is still open. Read both before non-trivial changes.

## Rules for this repo

- Changes reach `master` through pull requests. The `validate` workflow runs `npm test` and
  fails if `npm run grammar` would change the generated parser or the Grammar page; it must
  pass before a merge. Chosen 2026-11-21 so that the clients which vendor the parser and
  `kubb.js` (playdate-kubb's tests, the thingelstad.xyz gadget) only ever copy a checked state.

- `grammar/planet-kubb-notation.peggy` is the source of truth for syntax.
  `site/assets/notation-parser.js` and `site/spec/planet-kubb-notation.peggy` are generated by
  `npm run grammar`, so don't edit them by hand. The railroad diagrams in `site/spec/index.html`
  are rewritten between the `<!-- diagram:Rule -->` markers.
- `site/assets/kubb.js` is the tolerant reader that the Stats page uses. It warns instead of
  failing. Keep it and the grammar in agreement; `npm test` cross-checks them. Where it reads
  something the grammar refuses it must warn, and `conformance/reader.json` holds it to that.
- `conformance/archive.json` is how every archived game read under notation 1. It is the guard
  that old sheets keep their meaning, so `--write` never touches it. Retaking it
  (`tools/snapshot-archive.mjs --rewrite`) records a decision to change what an old sheet means.
- A change to the notation goes in three places together: the grammar, `docs/notation-2.md`,
  and a case in `tools/conformance-cases.mjs`. The header keys and their canonical order are
  listed in both the grammar and `canonical.js`; the suite fails if they drift.
- `games/` is generated by `tools/wiki2kubb.py`. Fix the generator, not the files. Then run
  `tools/build-site-data.py` to refresh `site/data/games.json`.
- The site has no build step: vanilla ES modules, root-relative paths, and light and dark CSS
  tokens in `site/assets/site.css`. Check layout at phone width with Playwright screenshots
  (headless Chrome here won't go below about 500px).
- The WordPress dump and its options table contain contact emails, and the wiki dump has user
  emails. Never copy them into the site or print them.

| What | Where |
|---|---|
| Live site | https://planetkubb.com. Notation page re-checked 2026-10-02 and unchanged. Who controls it today is unknown (possibly Garrick van Buren). |
| GitHub org `Planet-Kubb` | this repo (as `scoring`, 2014: the v11 scoresheet PDF and OmniGraffle source, now in `scoresheets/blank/`), `matches` (README only), `wiki` (`Team-Scores.py`, 2013), `PyKubb` (Jamie's 2014 Python notation parser; its token regex was `(?P<modifier>\d?)(?P<action>[irpqbf\-=kx])+`) |

`tools/archive/sqlrows.py` reads rows straight from a gzipped mysqldump without a MySQL server:
`schema_and_rows(path, table)` yields `(columns, row)`, with string values as bytes. It is
binary-safe and handles MySQL escapes. `tools/archive/tpl.py` splits nested MediaWiki
`{{templates}}` into `(name, {param: value}, offset)`. Both were scratch helpers for this dig.

## Decisions already made

- `4A` is a line 4 m in from the baseline, which is the center line. The 2017 glossary confirms
  that advantage lines are measured from the baseline. The old page text "on the baseline"
  contradicts its own `0A`.
- `G` means the throwing team resigns.
- 0B@T# uses the cumulative throw number. Garrick's 2013 "best possible stats" post gives Beta
  5 where the parser gives 6. Hit % and Efficiency match that post (100 / 87.5).
- Batons recorded as `-` after the king falls count as unthrown, and `kubb.js` warns about them.
- The `[First]` header is inferred from who took the king. 16 games opened with Team B, although
  the wiki always assumed Team A.
- Player tokens may contain `_` (`grant_scott`). The colon can be left out only for a lowercase
  player followed by an action that starts with a capital, a digit or a symbol.
